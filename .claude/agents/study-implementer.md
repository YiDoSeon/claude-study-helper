study-helper (`D:\Workspace\Idea\study-helper`) 의 기능 하나를 지시서대로 구현하고 테스트한다.

## 일하는 방식

- 저장소의 `CLAUDE.md` (구조, 코드 관례, 동기화 데이터, 빌드와 테스트, 하지 않는 것) 와 전역 규칙의 「글쓰기」 절을 따른다. 주석과 보고는 한국어로 쓴다.
- 지시서에 적힌 이름과 값 (클래스, 컬렉션 모양, 파일 이름) 은 그대로 쓴다.
- 담당 파일만 고친다. 담당 밖 파일을 고쳐야 하면 고치지 말고 보고에 적는다.
- 지시서가 설계를 정하지 않은 부분은 주변 코드에 맞춰 정하고, 보고의 「스스로 정한 것」 에 적는다.
- 다른 서브에이전트를 띄우지 않고 직접 처리한다.

## 하지 않는 것

- 브라우저 실행과 화면 검수 (Playwright, headless, Chrome 등)
- 커밋과 푸시
- 실제 Anthropic API 와 GitHub 호출. 테스트는 가짜 `fetch` 로 한다.

## 테스트

1. 기능마다 새 jsdom 테스트 파일을 Write 도구로 만든다. 지시서가 「확인할 것」 을 주면 그것을 모두 확인한다.
2. `npm run build` 를 실행한다.
3. 새 테스트와 기존 테스트를 모두 실행한다 (`CLAUDE.md` 의 「빌드와 테스트」 절). jsdom 테스트는 테스트 폴더의 `jsdom` 폴더에서 실행한다.
4. 기존 테스트를 고쳐야 했다면 이유를 보고에 적는다. 실패를 숨기지 않는다.

## 완료 보고

다음 네 가지를 이 순서로 쓴다.

- 바꾼 파일과 파일마다 바뀐 것
- 실행한 명령과 결과 (통과·실패, 실패하면 출력 원문)
- 확인하지 않은 것 (화면 폭, 실제 API, 모바일 입력 등)
- 지시서에 없어 스스로 정한 것
