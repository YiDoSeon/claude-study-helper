# 서브에이전트에게 일을 맡기는 방법

본 세션이 study-helper 작업을 서브에이전트에게 맡길 때 따른다. 승인 기준은 전역 규칙 (`C:\Users\doseon\.claude\CLAUDE.md` 의 「멀티 에이전트는 사용자 승인 후에만 쓴다」) 을 따른다.

## 누가 무엇을 하나

| 일 | 맡는 곳 |
|---|---|
| 설계가 정해진 구현과 그 테스트 | 서브에이전트, Sonnet 5.5 · effort medium |
| 노트 (`D:\Workspace\Idea\api-credit-notes\`) 반영 | 서브에이전트, Sonnet 5.5 · effort low |
| 설계 결정, 사용자 질문에 답하기 | 본 세션 |
| 원인을 모르는 버그 조사 | 본 세션 |
| 변경분 검토, 빌드와 전체 테스트, 커밋·푸시 | 본 세션 |

- 한 번에 하나만 띄우고, 끝난 뒤 다음 것을 띄운다.
- 작업 단위마다 새 에이전트를 띄운다. 다시 깨우는 것은 방금 끝난 작업의 검토 지적을 고칠 때뿐이다.

## 지시서에 넣는 것

1. 목표: 사용자가 원한 것과 확정된 설계. 본 세션이 정한 값 (클래스 이름, 컬렉션 모양 등) 은 그대로 적는다.
2. 담당 파일과 파일마다의 주제. 담당 밖 파일은 고치지 말고, 고쳐야 하면 보고에 적으라고 한다.
3. 근거: 읽어야 할 파일과 함수 이름. 이전 대화나 조사 로그는 넘기지 않는다.
4. 완료 기준: 빌드 성공, 새 테스트와 기존 테스트 전부 통과.
5. 규칙: 전역 규칙의 「글쓰기」 절, 이 저장소의 `CLAUDE.md`, 브라우저 금지, 커밋·푸시 금지.
6. 「서브에이전트를 추가로 띄우지 말고 직접 처리하라」

## 완료 보고 형식

- 바꾼 파일과 파일마다 바뀐 것
- 실행한 명령과 결과 (통과·실패 수, 실패하면 출력 원문)
- 확인하지 않은 것 (화면, 실제 API 등)
- 지시서에 없어 스스로 정한 것

## 끝난 뒤 본 세션이 하는 일

1. `git diff` 로 변경분을 읽는다.
2. 빌드하고 모든 테스트를 다시 실행한다.
3. 소스, 빌드 결과, 스테이징된 diff 에서 키 패턴 (`sk-ant-`, `github_pat_`, `ghp_`) 을 grep 한다. 테스트용 가짜 키 `sk-ant-fake` 는 scratchpad 에만 있어야 한다.
4. 지적할 것이 있으면 같은 에이전트를 깨워 고치게 한다.
5. 사용자에게 결과를 알리고 「커밋하고 푸시할까요?」 라고 묻는다.
